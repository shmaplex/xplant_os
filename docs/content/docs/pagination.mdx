---
title: Pagination
description: Page through lists with a cursor where it's offered, or with limit and offset.
---

List endpoints return one page at a time. `data` is a plain array, and there's no total count. Every list takes a `limit`:

| Parameter | Default | Notes |
| --- | --- | --- |
| `limit` | 50 | Page size, 1–200. Values above 200 are capped at 200. A missing, zero, negative or non-numeric value falls back to 50. |

How you ask for the next page depends on the list. Each list's reference page says which kind it is.

## Cursor lists (preferred)

Where a list offers a cursor, use it. The response carries `meta.next_cursor`: pass it back unchanged as `cursor`, with the same filters, to get the next page. It's `null` on the last page.

```json
{ "ok": true, "data": [ … ], "meta": { "next_cursor": "eyJ…" } }
```

```bash
curl "https://app.xplantpro.com/api/v1/…?limit=200&cursor=eyJ…" \
  -H "Authorization: Bearer $XPLANT_API_KEY"
```

- Treat the cursor as opaque: don't parse it, build it or store it for long.
- Keep the same filters and `limit` for every page of one walk.
- `cursor` can't be combined with `offset`.

A cursor picks up exactly where the last page ended, so records created while you're paging don't shift what you see.

## Offset lists

Lists without a cursor take `offset`, the number of records to skip (rounded down; a negative value becomes 0). **Keep asking until a page comes back shorter than your `limit`.**

```bash
curl "https://app.xplantpro.com/api/v1/plants?limit=200&offset=0" \
  -H "Authorization: Bearer $XPLANT_API_KEY"
# then offset=200, offset=400, … until a page has fewer than 200 items
```

Offsets count records at the moment you ask. If a record is added or removed ahead of your position while you're paging, the next page shifts: you can see one twice or miss one. For a mirror that must stay exact, sync from [change history](/docs/guides/change-history) with `since` instead of re-paging everything.

## In code

The SDK's `paginate` handles both kinds, so your loop doesn't change when a list moves to cursors:

```js tab="JavaScript" tab-group="lang"
import { XPlantClient, paginate } from "@shmaplex/xplant-sdk";

const client = new XPlantClient({ apiKey: process.env.XPLANT_API_KEY });

for await (const plant of paginate((page) => client.plants.list(page))) {
  console.log(plant.id);
}

// Extra filters go alongside the page:
for await (const event of paginate((page) => client.events.list({ entity: "explant", ...page }))) {
  // …
}
```

```python tab="Python" tab-group="lang"
import os
import requests

HEADERS = {"Authorization": f"Bearer {os.environ['XPLANT_API_KEY']}"}


def all_items(path, params=None, limit=200):
    """Walks a list with its cursor when it has one, or by offset otherwise."""
    params = {**(params or {}), "limit": limit}
    offset = 0
    while True:
        body = requests.get(
            f"https://app.xplantpro.com/api/v1{path}", headers=HEADERS, params=params, timeout=10
        ).json()
        if not body["ok"]:
            raise RuntimeError(f"{body['code']}: {body['error']}")
        yield from body["data"]
        meta = body.get("meta") or {}
        if "next_cursor" in meta:
            if meta["next_cursor"] is None:
                return
            params["cursor"] = meta["next_cursor"]
        else:
            if len(body["data"]) < limit:
                return
            offset += limit
            params["offset"] = offset


for plant in all_items("/plants"):
    print(plant["id"])
```

## Sensor readings

`GET /sensor-readings` returns readings newest first, takes a `limit` of up to 1,000, and has no `offset`: set the earliest reading you want with `since`. See [List sensor readings](/docs/api/sensor-readings/list-sensor-readings).
